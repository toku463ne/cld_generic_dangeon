# 1-2 実装前の数え上げ: 手の間に差がつく決定の割合と、窓の締切の壁

判断は [`docs/history/20260924.md`](../history/20260924.md) の「1-2 数え上げ: 差がつく決定の割合」。

## 概要

- 確かめたかったこと: 真の表で値付けしたとき、最善の手と2番目の手に差がつく決定がどれだけあるか。窓の長さと体力の帯ごとに数え、窓の締切の壁が出るかを見る（PLAN 1-2「実装前に数えること」）。
- 分かったこと: **壁は出る。窓が満腹から餓死までの長さ（1000 tick）より短いと、窓より長くもつ身体は足元の食料を見送る。1000 tick 以上では、足元に食料がある決定の 8〜9 割で「食べる」が単独で最善になり、2000 でも変わらない。** 差がつく決定は全体の約 2% にとどまるが、それは足元に食料がある決定（約 2%）とほぼ同じ集合で、知覚が無い以上、差がつきうるのはそこと地域の境目だけ。
- 次にすること: 窓の既定値を 1000 tick にして 1-2 を実装する。表は地域ごとの食料の数でキャッシュする（下の「計算量」）。

## 条件

| 項目 | 値 |
| --- | --- |
| コミット | ae210e5 |
| マップ | flat (64x48) / constrained (64x48) |
| tick 数 | 20000（全員が死んだシードはそこで終わる） |
| シード数 | 12（最初のシード 1） |
| 比較対象（base） | 窓の長さどうし（50〜2000 tick） |

**再現方法**:

```
go run ./cmd/count -what split -map flat -w 64 -h 48 -seeds 12 -ticks 20000
go run ./cmd/count -what split -map constrained -w 64 -h 48 -seeds 12 -ticks 20000
```

**数え方**:

- 1-1 の世界（無作為の対照）を 50 tick ごとに止め、生きている全個体について、可能な手それぞれの値打ち（窓の終わりに生きている確率）を `engine.World.Value` で出す。値付けは世界に戻さない（`TestValueChangesNothing`）。
- 予測の中身: 手を1つ取ったあと、行き先の地域で歩き続け、食料のあるタイルに立ったら食べる。出会う確率は1 tick あたり（その地域の地面の食料 ÷ 陸のタイル数）× `Speed`。体力は `EnergyBurn` 1 tick ぶんを単位に、tick ごとに正確に積む（`engine.TruthTable.NewSurvival`）。
- 「差がつく」は、最善と2番目の値打ちの差が 1e-12 を超えること。「食べるが単独で最善」は、食べる手の値打ちが他のすべての手を 1e-12 を超えて上回ること。
- 体力の帯は、その決定の時点の体力（上限 100 に対する 5 等分）。

## 読み方

- **壁の位置は計算どおり。** 体力 E の身体は、窓が E ÷ `EnergyBurn` tick より短ければ、どの手でも窓の終わりに確実に生きているので、食べても差がつかない。窓 300 では体力 30 以上、窓 500 では 50 以上で「食べる」が最善にならない。
- **1000 tick で寝る。** 満腹の身体でも 1000 tick で餓死するので、窓が 1000 以上なら窓より長くもつ身体はいない。1000 と 2000 の行はほぼ同じ。帯 80〜100 が 100% にならないのは、満腹に近い身体では食べても上限で切られて得る体力がほとんど無いため。
- **差がつく決定が全体の約 2% しかないのは、壁ではなく知覚が無いから。** 同じ地域の中では8方向の移動と待つが同じ値打ちになる（どれも1 tick ぶん体力を使い、同じ地域で歩き続けると予測する）。差がつくのは、足元に食料があるときと、移動が地域の境目を越えるときだけ。制約の地図で全体の割合が足元に食料がある割合をほとんど超えないので、境目を越える決定はまれ。
- **PLAN の「ほぼゼロなら値付けは世界を動かさない」は、この段階では当てはまらない。** 差がつく約 2% は、足元の食料を食べるかどうかの決定そのもので、[足元の数え上げ](20260924-1-2-underfoot.md)では、ここで必ず食べれば釣り合いの約 2 倍の頻度になる。

## 計算量

- 値付け1回（7 窓ぶん）: 約 1.5µs。
- 表の作成: 窓 1000 だけなら1地域あたり約 1.05 ms（`BenchmarkSurvival1000`）。制約の地図は4地域なので、毎 tick 作り直すと 1 tick に約 4 ms かかる。1-1 の 1 tick（約 2.5µs）の千倍を超える。
- **表は地域の地面の食料の数だけで決まる**（陸のタイル数と設定は変わらない）。食料の数でキャッシュすれば、近似なしで作り直しを数十回に減らせる見込み。1-2 の実装ではこうする。
