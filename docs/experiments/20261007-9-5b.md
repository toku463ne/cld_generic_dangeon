# 9-5b 予算の大きさを遺伝子の枠にし、消耗で価格を付ける（`AllotBudget`・`BudgetBurn`）

判断は [`docs/history/20261007.md`](../history/20261007.md)・[`20261008.md`](../history/20261008.md)。`unsized`（9-5a、予算は全員 1）を基準に、base（5 段・1 段 1.25 倍・消耗が予算に比例）と `unpriced`（同じ枠で価格なし——前身で予算が際限なく上がった形）を比べた。**flat は e4d7b07（表の天井を丸める前）、patches・constrained は 361b18e（`FullStep` 入り。flat の初回は patches が OOM、constrained がメモリ逼迫で止められたため、軽くしてからユーザの指示で取り直した）。** `FullStep` が世界を動かさないことは [fullstep](20261007-fullstep.md) で確かめてある。

## 1. 概要

- 確かめたかったこと: 予算の大きさを離散の段として親から継がせ、1 tick の消耗を予算に比例させたとき、(a) 価格が無ければ前身のように予算が上がり続けるか、(b) 価格があれば横ばいになるか、(c) 世界がどう動くか、(d) 子の予算と親の予算の相関（`VISION.md`「予算の大きさは親の予算の影響を受ける」）が正か。
- 分かったこと（3 地図）:
  - **価格が無いと予算は天井まで上がる**: `unpriced` は 3 地図とも成人の平均予算 1.37〜1.39（最大段 1.5625）、最大段の成人 50〜51%（引きは 20%）。世代 10 で 1.31〜1.35 に達し、以後は天井に貼りつく。後半 − 前半のドリフトは flat +0.070 ± 0.015 で有意、patches +0.012 ± 0.012・constrained +0.042 ± 0.026 で誤差内——**上がりきるのが tick 20000 より前なので、後半 − 前半では見えない**（完了条件の書き方の失敗。世代の表と最大段の割合が本体）。
  - **価格があると中立の少し上で横ばいになる**: base の成人の平均予算は flat 1.10・patches 1.04・constrained 1.12、ドリフトは +0.004 ± 0.017・+0.015 ± 0.023・−0.009 ± 0.016 で 3 地図とも誤差内。最小段の成人 2〜9%・最大段 3〜7%（引きは各 20%）で、両端が削られ中央に集まる。
  - **世界は価格を払って弱くなるが、地図で大きさが違う**: 個体数は flat −26.8 ± 6.9（−27%、崩壊 1/12）、patches −6.9 ± 4.3（−6%）、constrained −7.2 ± 2.2（−10%）。**成人到達率は 3 地図とも −0.06**（両端の段を引いた子が成人前に死ぬ——9-3 の変異の重荷と同じ形）。`unpriced` は 3 地図とも増える（+12%・+7%・+8%）。
  - **子の予算と親の予算の相関は 3 地図とも +0.66〜+0.70**（`VISION_CHECKS.md` の判定を満たす）。
  - 他の枠への波及: 視野が最大の成人の割合は base で 3 地図とも下がる向き（−0.073 ± 0.055・−0.058 ± 0.025・−0.050 ± 0.039）——消耗の価格が、視野を買う余裕を削る。
- 予想との照合: (a) 当たり（ただし「上がり続ける」ではなく「天井に貼りつく」——5 段なので上限がある）。(b) 当たり（横ばいの段は中立より上）。(c) 「flat・patches で減り constrained は誤差内」は半分外れ——3 地図とも減り、flat がいちばん大きく（−27%、1 崩壊）、constrained も有意（−10%）。(d) 当たり。
- **追記（2026-10-07、[fullstep](20261007-fullstep.md) の `exact` 列、同じ世界を計器を直して読んだもの）**: base の予算のドリフト（後半 − 前半）は 0.004 ± 0.017 で誤差内、成人の平均予算は 1.097 ± 0.018。**完了条件「base で誤差内・`unpriced` で有意に正」を flat で満たす。**
- 速さ: `cmd/experiment` の 1 本が flat で約 2 倍、constrained では `unsized` 30 秒に対し base 4 分（8 倍）。表の作り直しが原因（`docs/history/20261007.md`）。
- 次にすること: 価格の形をユーザと決める（線形のまま受け入れる／消耗 ∝ 予算^k で k > 1／中立の段を上げる）。
