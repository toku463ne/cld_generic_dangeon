# 振動する身体の数え上げ（`cmd/count -what jitter`、9-4 のあと）

ユーザがクライアントで見つけた「その場で小刻みに動く身体」（flat、seed 1、tick 15643 付近）を数えた。コミット 2ee76cb の世界（9-4 base）。

```
go run ./cmd/count -what jitter -map flat -w 64 -h 48 -seeds 1 -seed0 1 -ticks 12000
```

振動の定義: 起きていて、直近 60 tick のうち 45 tick 以上動いたのに、x・y とも 2 タイル以内に留まっている。tick 5000 より後を数える。

## 読み

- **振動は起きている身体 tick の 2%**。1シードで 117 体・203 回、1回あたり約 40 tick。
- **振動中の決定の 80% は最善が同点**（振動していない決定では 54%）。きっかけの半分は「足元の食料の有無が変わった」。計画の食料は距離 0 か 1 が 66%。体力は 0.6〜0.9 が 72%——飢えてはいないが満腹でもない帯。
- **仕組み**: 食料のタイルに立った身体にとって、「今食べる」と「一歩離れてから戻って食べる」は窓の中の生存の確率が同じ（どちらも 0）で同点になる。同点は向きの維持で決まるので、身体は食べずに歩き去る。視野 0 ならタイルを離れた瞬間に食料が見えなくなり、覚えている食料へ歩く手（5-2）が唯一の最善になって戻る。戻れば足元の食料でまた決め直し、また同点、また歩き去る。視野 1 以上でも「見えている食料へ歩く」と「移動を続ける」が同点で、同じ形の往復が起きる。体力が落ちて食べる手が単独の最善になるまで続く（例では 140 tick、体力の 16% を歩いて失った）。
- **対の損得にも繋がる**: 振動中の決定の 11% に交配の手が候補にあり、要求の相手の周りでも同じ往復が起きうる。

## 候補の直し方（ユーザ判断）

1. **同点なら、計画の食事に一番早く届く手を取る**（`Arrive` が最小の手。今食べる手は 0）。向きの維持より先に適用する。「今食べられるのに歩いてから戻る」を消す最小の規則。満腹に近い身体が食べる割合が上がり、食料の無駄（上限を越えた分）がわずかに増える可能性がある。
2. 食べる手と移動の同点を、消費（`TieSpend`）と同じ形で「食事までに燃やす体力」で破る——1 と同じ向きで、`Spend` の枠組みに乗せる形。
3. 何もしない——2% の身体 tick で、世界の指標は動かない可能性が高い。見た目の違和感と体力の無駄だけ。
