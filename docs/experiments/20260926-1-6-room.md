# 1-6 数え上げ: 学ぶ2つの行が決定を入れ替える余地

判断は [`docs/history/20260926.md`](../history/20260926.md) の「1-6: 余地の数え上げ」。前の数え上げは [1-6-learn](20260926-1-6-learn.md)。

## 概要

- 確かめたかったこと: ユーザと決め直した 1-6 の2つの行（自分が通ったタイル・交配の行）を、真の値で知っていたら、決定の最善がどれだけ入れ替わるか。
- 分かったこと: **通ったタイルの行で 17%（平坦）・21%（制約）の決定の最善が変わる**。そのうち約 2 割は真後ろへの手。死ぬ確率が 0 に丸まって何も入れ替わらない決定は 3〜4% だけ。**交配の行（子になる割合 0.115）では、交配を選んだ決定の 91〜92% が見送りに変わる**。どちらかで変わる決定は約 3 割。地域の行（0.0〜0.1%）と違い、学ぶ余地は大きい。
- 次にすること: 1-6 を実装する。ただし (1) 通ったタイルの行は、1体が一生で集める証拠が少ない（入るタイルの 14〜18% が通ったタイル、一生で約 45 回）ので、親の行（地域）へ強く引き寄せられ、真の値ほどは効かないはず。(2) 交配の行を学ぶと交配が激減し、出生が保てるかが危うい（`VISION.md`「簡単に絶滅しない」）——予想に書いて測る。

## 条件

| 項目 | 値 |
| --- | --- |
| コミット | e35ff26（世界のコードは db0279c のまま） |
| マップ | flat (64x48) / constrained (64x48) |
| tick 数 | 40000（決定は tick 5000 より後） |
| シード数 | 12（最初のシード 1） |
| 世界 | base（跳ね返しなし）。学習は無く、数え上げが横で読むだけ |

**再現方法**:

```
go run ./cmd/count -what room -map flat -w 64 -h 48 -seeds 12 -ticks 40000
go run ./cmd/count -what room -map constrained -w 64 -h 48 -seeds 12 -ticks 40000
```

**数え方**: 決定を設定の能力で値付けし直し（`World.Value`）、身体の手が最善の中にあった決定だけ読む（約 99%）。
- 通ったタイルの行: 最善の手（同点）のうち「動き続ける」続きの移動について、その向きの先 8 タイルに、200 tick 以内に自分が離れたタイルがいくつあるかを数える。通ったタイルは乏しい（[1-6-learn](20260926-1-6-learn.md) の (D) で 3〜4 割）ので、死ぬ確率が 0 に丸まっていなければ、先に通ったタイルが多い手ほど死ぬ確率がわずかに上がり、同点から外れる。身体の手が、同点の中で通ったタイルが一番少ない手でなかった決定を「変わる」と数えた。効きの大きさは小さい（窓の中で入るタイルの 3% ほど）ので、もともと差のある手の順位は変えないとした。
- 交配の行: 交配を選んだ決定で、交配の死ぬ確率 − 0.5 × 0.115 が、交配以外の最善の死ぬ確率より大きくなるもの。
