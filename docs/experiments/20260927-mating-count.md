# 交配の段階の事前カウント（`mating`）

判断は [`docs/history/20260927.md`](../history/20260927.md) の「交配の段階の事前カウント」。

## 1. 概要

- 確かめたかったこと: `VISION.md` の新しい交配の項（個体の位置を伝え、受け取った身体が向かい、着いたら申し出る）が交配を増やすには、今の交配の詰まりがどこにあるか。(a) 申し出が子にならない理由、(b) 一番近い相手までの距離、(c) 位置が古びる速さ。3-7 の世界で数えた。
- 分かったこと:
  - **詰まりは出会いではなく、相手（ほとんど雌）が払えないこと。** 申し出は1シードあたり 8.6 万〜14.3 万（出生の約 20〜40 倍）あり、子になるのは 1.7〜3.0%。失敗の **83〜88% は相手が自分の分を払えない**（雌の出産の分は 45。払えないと交配の手を持てない）。払えるのに交配を選ばなかったのは 10〜14%。相手が視界から出た・別の身体に申し出ていたは合わせて 0.1%。**身体は相手の体力が見えない**（`NODE.md`）ので、雄は払えない雌に申し出続ける。
  - 出会いの余地: 交配できる成人から一番近い交配できる異性の成人は、視界の中 12〜18%、2〜5 タイル 51〜53%、6〜10 タイル 24〜29%、それより遠い 6%。
  - 位置は速く古びる: 身体は 25 tick で 3.6〜4.0、50 tick で 6.3〜7.3、100 tick で 10〜12 タイル動く。
- 読み: 個体の位置を伝える形（M-1・M-2）は出会いを増やすが、出会いは詰まっていない——申し出は十分あり、相手の多くが払えない。**交配を増やすのに効くのは、交配できる状態にある（払える）ことが相手に伝わること**——`VISION.md` の「交配要求の発信」を、払える身体が出す要求として入れれば（M-3）、払えない雌への申し出が減り、払える雌に相手が集まる。
- 次にすること: 交配の段階の順を M-3（交配要求の発信）から始めるように組み替えるかを、ユーザと決める。

```
go run ./cmd/count -what mating -map flat -w 64 -h 48 -seeds 12 -ticks 20000
go run ./cmd/count -what mating -map constrained -w 64 -h 48 -seeds 12 -ticks 20000
```

申し出の行方は、申し出を実行した tick の相手の状態で分けた（視界の外／別の身体に申し出ていた／自分の分を払えない／払えるのに交配を選んでいない／申し出返していた）。払えるかは相手の体力と自分の分（雌 45、雄 5）から数えた。
