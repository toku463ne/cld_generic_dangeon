# 3-5 の続き: 数が少ないと増えにくくなる罠を確かめる（`allee`）

判断は [`docs/history/20260927.md`](../history/20260927.md) の「3-5 の罠の確かめ」。前は [3-5](20260927-3-5.md)。

## 1. 概要

- 確かめたかったこと: 3-5 で制約の地図の 1 / 12 が崩壊したのは「身体が薄くなると視界に相手が入りにくく出生が減り、寿命があると相手に出会う前に老いで死ぬ」罠か。
- 分かったこと:
  - **「相手に出会う前に老いで死ぬ」は外れ。** 老いで死んだ成人のうち子を持たなかったのは 1.9〜2.8% だけで、最後に相手が視界にいたのは死ぬ 124〜143 tick 前。老いで死ぬ身体は、ほとんどが子を持ち、最近まで相手を見ている。
  - **数が少ないと相手が見えにくいのは本当**（制約・base）: 個体数 80 未満で相手が視界にいる割合 0.058、140 以上で 0.127〜0.131（約半分）。成人 1000 tick あたりの出生も 80 未満で 0.62、140〜170 で 0.86、170 以上で 1.03。ただしこれは全シードの時点を個体数で分けた横断の読みで、「出生が多い時期だから個体数が多い」という逆向きの因果と区別できない。
  - **寿命が無い世界（`ageless`）では個体数が 140 を下回らない**。寿命は個体数を下げ、出生の少ない帯へ世界を押し出している。
- 読み: 寿命の効き目の中心は、繁殖できる期間（成人の 1000 から 3000 まで）を区切ること。個体数が下がるぶん相手が見えにくい帯に入り、出生がさらに少し減る——罠は弱いが本物で、寿命がそこへ世界を近づけた。
- 次にすること: 寿命を延ばす（案 A、4000）か、相手を探す仕組み（案 B、交配の段階）かをユーザと決める。

## 2. 条件

| 項目 | 値 |
| --- | --- |
| コミット | c074971 |
| マップ | flat / constrained (64x48) |
| tick 数 | 40000（tick 5000 より後） |
| シード数 | 12（全シードの成人の tick を合わせて読む） |
| 条件 | base（3-5、`Lifespan` 3000）、`ageless`（3-4） |

```
go run ./cmd/count -what allee -map constrained -w 64 -h 48 -seeds 12 -ticks 40000   # -variant ageless、flat も
```
