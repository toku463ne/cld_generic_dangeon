# 1-4 数え上げ: 速さの相手はどの能力か（侵入）

判断は [`docs/history/20260926.md`](../history/20260926.md) の「1-4: 数え上げ」。

## 概要

- 確かめたかったこと: 1-3 の世界で、生まれた身体の半分の能力（速さ・体力の上限・消耗・上限と消耗）を ×1.25 か ×0.8 に振り、残り半分と比べたとき、どの能力に選択勾配があるか。速さと取り合わせる能力を選ぶ。
- 分かったこと: **速さは上げても下げても生涯出生数が大きく動く**（+0.61〜+0.70・−0.67）。**体力の上限・消耗は、設定の値より良くしても生涯出生数はほぼ動かず、悪くすると大きく下がる**（上限 ×0.8 で −0.65〜−0.68、消耗 ×1.25 で −0.78〜−0.82）。燃費を良くすると成人到達率は上がる（+0.12）が、成人1体あたりの子の数が下がり（−0.29〜−0.36）、打ち消し合う。
- 次にすること: 速さの相手を **(a) 体力の上限**にする（`VISION.md` の遺伝子の一覧にある能力で、下げる側の勾配が両方の地図で有意）。予算で速さを上げると上限が下がり、その損が速さの得に追いつくところで釣り合うはず。

## 条件

| 項目 | 値 |
| --- | --- |
| コミット | 4010101（世界のコードは fb3c53a。数え上げが `World.SetBuild` で能力を振る） |
| マップ | flat (64x48) / constrained (64x48) |
| tick 数 | 40000（成人到達率と生涯出生数は tick 5000 より後に生まれた身体、成人1体あたりの子の数は tick 5000 より後に死んだ成人） |
| シード数 | 12（最初のシード 1） |

**再現方法**:

```
go run ./cmd/count -what invade -map flat -w 64 -h 48 -seeds 12 -ticks 40000
go run ./cmd/count -what invade -map constrained -w 64 -h 48 -seeds 12 -ticks 40000
```

振る身体は数え上げ側の乱数で選ぶ（世界の乱数の引き方は変えない）。燃費は、移動が行動の約 98% なので、1 tick あたりの消耗（`EnergyBurn`）で代えた。

## 読み方

- **速さだけが両側に勾配を持つ。** 速さは食料に出会う割合（真の表の3行目）と見えている食料へ着く tick 数に効く——入ってくる量を増やす。体力の上限と消耗は、蓄えと出ていく量に効くが、1-3 の世界の身体はほとんど空腹で上限に届かず（上限を上げても使われない）、消耗を減らして生き延びた分は子の数に回らない（下の2つ目）。
- **燃費を良くすると成人1体あたりの子の数が下がる。** 死ぬ確率は体力に対して S 字で、交配を見送るのは坂の途中の身体（[1-3](20260926-1-3.md)）。消耗が小さい身体は同じ体力でも tick で数えて長く持つので、子の代金 25 が坂の上で効く位置にいることが増え、見送りが増えると読める（この数え上げでは確かめていない）。
- **選ぶ候補。** 予算の取り合いでは、速さを上げる身体は相手を下げる。速さの得（+0.6）と相手を下げる損（−0.65〜−0.82）はどれも非ゼロなので、どの候補でも配分は端に張り付かず、途中で釣り合うはず。相手を良くする側は勾配がほぼ 0 なので、配分が設定の値より相手の側へ寄ることはまず無い。**`VISION.md` の遺伝子の一覧にある「最大体力」を選ぶ**（燃費は一覧に無い）。(c) は損が大きいが代価を2つ重ねるので、1つで足りる以上は採らない。

## 画面横断時間の見積もり

クライアントは地図全体（64 タイル、1 タイル 12 ピクセル）を出し、既定は 1 フレーム 1 tick（60 フレーム/秒）。速さ 0.25 タイル/tick の身体が画面を横切るのは 256 tick、**×1 で 4.3 秒、×4 で 1.1 秒**。遊ぶズーム（地図の一部だけを出す）はまだ無いので、これを 1-4 の中央値の身体の出発点にする。
