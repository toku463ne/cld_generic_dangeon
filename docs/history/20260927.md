- **3-2 のあとの扱い（ユーザの申し送り・確定版）**: 3-2 で母が出産の代金で死に、成人の女が 12% になった件に、提示した A（産後の休みを約 1100 tick に延ばす）・B（出産の代金を下げる）・C（そのまま）ではなく、**戻ってくる食料の一部を休んでいる母に直接配る**規則を足す。何も無いところから体力が生まれる自動回復は保存則に反するので採らない。配る確率は、母の相手（最後の子の父）が今同じ地域にいるかで変わる（いなくても 0 にはしない）。段階の番号をずらし、3-3 をこの規則、3-4 を寿命と老いによる死、3-5 を能力の年齢の曲線にした。
- **3-3 の事前カウント**（[20260927-3-3-count](../experiments/20260927-3-3-count.md)、`cmd/count -what provision`）: 休んでいる母のいる地域で母1体あたりに戻る食料は 1 tick あたり約 0.05 単位。相手が同じ地域にいる割合は平坦 0.97（地域が1つ）・制約 0.82。休み明けの母の体力は約 52。配る確率を仮に、相手がいれば 0.07、いなければ 0.035 とした（休みのあいだに約 42 を受け取る見込み）。
- **3-3 を実装した（`Provision`）。** 戻る食料1単位ごとに、その地域で休んでいる母から1体を無作為に選び、相手（最後の子の父。母が `Partner` に持つ）が今同じ地域にいれば `ProvisionWith`（0.07）、いなければ `ProvisionAlone`（0.035）の確率で、その単位を地面に置かず母に配る（`FoodEnergy`、上限まで）。配った単位は現れてすぐ食べられた単位として帳簿（`FoodLedger.Provisioned`）と `Stats.Provisioned`（地域ごと）に数え、`cmd/experiment` の出来事の表と対の差に出す。地面に出ないので、地域の行の証拠（視界に入ったタイル）や地面の食料の表には入らない。3-2 は条件 `unfed` として variant の鎖に入れた。スナップショットの版を 13 に上げた。
- **3-3 の測定**（[20260927-3-3](../experiments/20260927-3-3.md)）: 完了条件を満たした。`unfed` との差で、成人のうち女の割合 0.12 → 0.23、出生 +47〜61%（餓死も同じだけ）、成人到達率 −0.04〜−0.05、制約の地図の個体数 +37.25 ± 8.40（3-2 の低下を取り戻した）、崩壊 0。予想の外れ: 休み明けの母の体力は 52 → 58〜59 にしか上がらなかった（予想 90 前後）——出生が増えて休む母が 11 → 19 体になり、母1体あたりに戻る食料が 0.05 → 0.03 に薄まった。母が増えれば1体あたりが薄まる形なので、確率を上げても同じ向きに薄まる。値は仮のまま次（3-4 寿命）へ進む。
- **食料の戻る確率の掃引（ユーザの申し送り）**: 3-3 で女の割合（0.23）と産後に死ぬ割合（80〜83%）が改善しきらない原因を切り分ける——配分と回復の設計そのものの欠陥（頭数が増えると1体あたりが薄まる問題は、どの食料の水準でも再発する）か、この地図の食料が単に貧しいだけか。規則は何も変えず、`FoodReturn` だけを 1・2・4 倍（条件 `base`・`food2`・`food4`）にして同じ指標を測る。素直に改善していけば設計は健全で、残りは最後の地図の調整の範囲。頭打ちなら、頭数に依存しない配分の形に立ち返る。食料は上限（`FoodCap`）までしか地面に無いので、戻る確率を上げても上限に張り付けばそれ以上は増えない——地面の食料の上限に対する割合も一緒に見る。測定のために、条件 `food2`・`food4`、報告の「成人のうち女の割合」、`provision` の「休んでいる母1体が休みのあいだに配られた体力」を足した。
- **食料の掃引の結果**（[20260927-3-3-food](../experiments/20260927-3-3-food.md)）: 食料の戻る確率を 2・4 倍にすると、個体数はほぼ 2・4 倍になる（平坦 167 → 337 → 663、制約 167 → 331 → 654）が、**1体あたりの指標はどれも動かない**——成人のうち女の割合 0.22〜0.24、女が最後の出産から 1000 tick 以内に死ぬ割合 78〜83%、休みのあいだに母1体が受け取る体力 21〜25、休み明けの母の体力 58〜60。休んでいる母の数が食料と同じだけ増えるので、1体あたりの配分は変わらない。地面の食料は上限の 6〜7% で、上限は効いていない。**申し送りの読み方では「改善しない」＝構造の問題**: この世界の1体あたりの条件は、食料の水準ではなく身体の振る舞い（産んで増え、食料と釣り合うまで）で決まる。地図の調整では解けない。配分の仕組み（頭数に依存しない形）か母の振る舞いか、どちらに立ち返るかユーザに確かめる。
