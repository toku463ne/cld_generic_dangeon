## 自律で進む前に、クライアントで中間を見られるようにした

**ユーザの指示**: 段階ごとの承認をやめ、`VISION.md` をなるべく実現するよう自律で進む（`CLAUDE.md`「進め方」）。その前に、動いている世界を見られるようにする。自律で進むと、6000 tick 周期の誤読（実は 300 tick の周期を 2000 tick ごとの表で読んだ見かけ）のような勘違いに気づくのが遅れるため。

**何をしたか**

- 見るだけのクライアント（`cmd/client`）は 1-2 の前から有った（`MEASURE.md`「UI での再生」）。**足りなかったのは、これまでの勘違いを目で見つけるための道具**なので、それを足した。
  - **履歴の帯**: tick 0 からの個体数と地面の食料。**1ピクセルに入る tick の最小と最大を描く**ので、1ピクセルより速い周期は帯になり、遅い偽の波にはならない（6000 tick の誤読の形）。
  - **軌跡**: 直近 300 tick の位置。閉じ込め・局所の循環・縁を回り続けるといった、1-2q で数えて初めて分かった捕まり方は、軌跡なら一目で見える。
  - **1体を追う**: クリックか `f`（体力が一番少ない個体）で追い、視界・向き・直前の決定の手と死ぬ確率・どの続きで読んだかを出す。意思決定トレース（`NODE.md`「予測の唯一の実装」）をそのまま画面に出す形。
- **描画を `view` パッケージに移し、`cmd/shot` を足した。** 同じ絵を PNG に書く。ebiten は import しただけで GLFW を初期化し、画面が無いと panic する（`DISPLAY` を外して確かめた）。1つのバイナリに `-shot` を足す形は採れなかった。`cmd/shot` は、**自律で進むあいだに Claude 自身が世界を見るための道具**でもある（PNG は読める）。あわせて、描画のテストが画面の無いところで走るようになった。
- 描画は標準ライブラリの `image` だけで行い、窓はそれを毎フレーム ebiten の画像へ書き写す。窓と PNG が同じ絵になることを優先した。ebiten の `vector` で描き続ける形は、PNG 側に2つ目の描画を書くことになるので採らなかった。
- 追っている個体の決定は `World.SetTrace` で写す。トレースは乱数を引かず世界に書かない。**追う・軌跡・描画をしても世界の指紋が変わらない**ことをテストにした（`view/view_test.go`）。
