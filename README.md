## 速さ（壁時計の秒数）

```
GOMAXPROCS=1 go run ./cmd/speed
GOOS=js GOARCH=wasm go build -o speed.wasm ./cmd/speed && node "$(go env GOROOT)/lib/wasm/wasm_exec_node.js" speed.wasm
```

世界を `-grow`（既定 20000）tick 育て、次の `-ticks`（既定 10000）tick にかかった秒数と平均の個体数、保持している生存の表の数・ヒープ・セーブの大きさ、育った世界をセーブして読み込み、温めた（`World.Warm`。セーブが名指しした生存の表を先に作る。読み込み画面の役）ときと温めないときの、それぞれ直後の `-cold`（既定 1000）tick の秒数を出す。`-map`・`-w`・`-h`・`-variant`・`-seed`（既定 5）・`-food`（食料の上限。個体数を揃えるため。0 は条件の値）。何を目標にしているかは `PARAMETERS.md`「性能の上限」。

## 実験

```
go run ./cmd/experiment -map flat -w 64 -h 48
```

| オプション | 意味 |
| --- | --- |
| `-map` | 地図。`flat`（全面が陸・地域1つ）/ `constrained`（地域4つ・陸を二分する水の帯） |
| `-w` / `-h` | 地図の幅・高さ（タイル数）。必須 |
| `-seeds` | シード数（既定 12。1-5 で確定、`PARAMETERS.md`） |
| `-seed0` | 最初のシード（既定 1） |
| `-ticks` | 1回の実行の tick 数（既定 40000。1-5 で確定、`PARAMETERS.md`） |
| `-variants` | 比べる条件をカンマ区切りで。先頭が base（既定 `base`）。`base` は既定の設定、`random` は窓 0（無作為に選ぶ 1-1 の対照）、`blind` は視界なし・向きを保たない（1-2 の1回目）、`restless` は視界ありで向きを保たない（1-2p）、`straightback` は向きを保つが真後ろへ跳ね返る（1-2q）、`everytick` は毎 tick 決める（1-2r）、`nobreed` は交配しない（1-2e）、`bounce` は塞がれた向きを跳ね返し、真後ろなら 45° 曲がる（1-5）、`drawreverse` は 1-5 のうち跳ね返しが真後ろになるときだけ同点の中から無作為に選ぶ、`tight` は配分の逓減を強める（`AllotCurve` を半分に。上を締めた世界）、`drawn` は配分を親から継がず毎回引く（衝突あり）、`overlap` は身体どうしがすり抜ける（1-4）、`fixed` は予算を配らない（全員が設定の能力。1-3） |
| `-floor` | 崩壊の下限。個体数がこれ以下になったシードは、そこで計算を打ち切る（既定 20。1-5 で確定、`PARAMETERS.md`） |

標準出力に `MEASURE.md` の形式のレポート（§2〜§9 と補助の表）を出す。§2 には代表シード・定常化 tick と、それを再生する `cmd/client` のコマンド行（「UI での再生」）も出す。崩壊したシードは代表シードの候補から外すので、全シードが崩壊した実験では出ない。tick ごとの表は、生存しているシードだけの平均と生存シード数を出し、全シードが下限を割ったあとの行は省く。§5 のあとに「成人到達率」「占有地域数と個体数の谷」（崩壊しなかったシードの tick 1 以降の最小の人口）「判断のきっかけ」（決定の割合と、きっかけごとの内訳）を出す。予算を配る条件が base なら「配分と生涯出生数」（速さへの配分ごとの生涯出生数、速さの側 − 上限の側の対の差、チェックポイントごとの生きている身体の配分の平均・標準偏差・最遅／中央値／最速の速さ・最速 ÷ 中央値、配分の平均の最後の 4 分の 1 − その前の 4 分の 1、中央値の身体の画面横断時間）も出す。予算の帳簿が閉じない tick があれば、その場で止まる。「動き方」（1000 tick の変位と、縁＝地図の端か水の隣のタイルにいる割合）も出す。§1 概要は人が書く。シードごとの実行時間は標準エラーに出す。保存則の検算が合わない tick があれば、その場で止まる。

## クライアント（見る）

```
go run ./cmd/client -map constrained -w 64 -h 48 -seed 7 -from-tick 840
```

| オプション | 意味 |
| --- | --- |
| `-map` / `-w` / `-h` | 地図と大きさ。`cmd/experiment` と同じ。必須 |
| `-variant` | 条件（既定 `base`） |
| `-seed` | 世界の種（既定 1） |
| `-from-tick` | この tick まで描画せずに計算し、そこから描画する（既定 0） |
| `-scale` | 1タイルあたりのピクセル数（既定 12） |
| `-follow` | 追う個体。ID か `hungriest`（`-from-tick` の時点で体力が一番少ない個体）か `median`（その時点で速さが中央値の個体）。既定は追わない |

実験のレポートに出た「UI での再生」の行をそのまま叩けば、その実験の典型的な1本を定常化 tick から見られる。

操作: スペースで一時停止、一時停止中は → で1 tick 進む、↑↓ で速さ（1フレームあたり 1〜64 tick）、`[` `]` で下の履歴の幅（1ピクセルあたり 1〜256 tick）、クリックでその個体を追う（何も無いところをクリックでやめる）、`f` で体力が一番少ない個体を追う、`t` で全員の軌跡。`c` で追っている個体を操作する（もう一度 `c` でやめる）: `w` `a` `s` `d` で移動（2つ押すと斜め）、`e` で食べる、`r` で視界の成人と交配を申し出る。何も押さなければ待つ。操作している個体は毎 tick、他の個体と同じ手の中から選ぶ（できない手を押したときは、その tick は値付けが選ぶ）。

画面:
- 地面の色は地域、青は水、赤い四角は食料、丸は個体（白いほど体力が多く、黒いほど餓死に近い）。軌跡は直近 300 tick の位置。
- 追っている個体は黄色（操作していると左上に `PLAYED`）。枠は視界、線は向き、食料へ伸びる線は直前の決定で歩いて食べると読んだ食料。左上の文字に体力・年齢・向き、今の意図とそれを決めた tick、直前の決定（括弧内はきっかけ）の手を点数の低い順に出す（`via` はその確率をどの続きで読んだか。交配の手には `child 1`）。
- 下の帯は tick 0 からの履歴で、右端が今。白が個体数、赤が地面の食料、0 からの目盛り。縦の線は 1000 tick ごと（1ピクセル 64 tick 以上では 10000 tick ごと）。**1ピクセルに入る tick の最小と最大を縦の線で描く**ので、1ピクセルより速い周期は帯として見え、遅い波のようには見えない。

## 画面の無いところで見る

```
go run ./cmd/shot -map constrained -w 64 -h 48 -seed 2 -from-tick 20000 -follow hungriest -trails -out shots -shots 4 -every 300
```

`cmd/client` と同じ絵を PNG に書き、左上に出る文字を標準出力に出す。オプションは `cmd/client` と同じものに加えて、`-out`（書き出すディレクトリ。必須）、`-shots`（枚数。既定 1）、`-every`（間の tick 数。既定 300）、`-trails`（全員の軌跡）。ファイル名は `地図-条件-s種-t tick.png`。ebiten は import しただけで画面を要求するので、描画は `view` パッケージに置き、窓を開くのは `cmd/client` だけにしてある。
